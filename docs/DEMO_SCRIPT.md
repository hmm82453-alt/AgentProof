# 比赛演示脚本

## 0:00 - 0:30 作品定位

“这是一个服务端可编排、可验证、可恢复的多 Agent 撤离规划原型。重点不是让
五个 Agent 聊天，而是让每一条结论都有来源，每一次失败都能触发具体修正。”

打开 <http://127.0.0.1:8000>，指出顶部的“服务端编排”状态。

## 0:30 - 1:10 任务输入

展示零号大坝、3 人、稳健搜打、红狼 / 蜂医 / 露娜、31.5kg。

说明三个并行 Agent 会先生成草稿，再交换彼此结果，而不是各算各的。

## 1:10 - 2:20 第一轮冲突

点击“开始协同规划”：

1. 地图 Agent 广播资源点、撤离条件和风险节点。
2. 三个并行 Agent 同时进入工作中状态。
3. 协作黑板出现风险、物资、干员之间的消息交换。
4. 校验 Agent 发现后卫延迟 18 秒，与风险窗口冲突。
5. 第一轮显示红色拦截和具体修改指令。

## 2:20 - 3:10 第二轮收敛

展示：

- 路线切换为外环
- 烟雾从 2 颗调整为 4 颗
- 后卫接管点提前到第一个转折点
- 风险指数下降
- 校验 Agent 六项检查全部通过

切换到“路线”“资源”“协同”“仲裁”标签，说明结果不是一段空泛总结。

## 3:10 - 3:45 平台中心

点击“平台中心”：

- 运行记录：完整事件已经持久化
- Agents：展示能力、工具权限、优先级和版本
- 工作流：展示阶段链和最大轮次
- 工具：展示可供 Agent 调用的确定性工具
- 评测：运行 8 个标准场景并展示通过率、轮次和耗时

## 3:45 - 4:15 工程价值

说明：

- 服务端通过 SSE 推送真实运行事件
- 每轮保存快照，失败后可创建恢复分支
- FastAPI 和 Docker 可独立部署
- MCP Server 可与外部 Agent 客户端连接
- 无模型密钥时仍能完整演示，配置密钥后自动启用 LLM

## 收尾话术

“我们把 Agent 的输出变成了可验证的证据链：谁说、依据什么、传给了谁、
哪一步失败、下一轮改了什么，都可以从运行记录中回放。”
