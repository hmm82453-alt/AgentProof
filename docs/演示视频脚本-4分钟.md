# AgentProof / 撤离线

## 4 分钟演示视频录制脚本

版本：2026-11-20

建议成片时长：4 分 00 秒到 4 分 20 秒

## 一、录制前准备

- 使用 1920x1080、30 fps、MP4/H.264 录制。
- 浏览器窗口最大化，关闭书签栏、通知、无关标签页和开发者工具。
- 页面缩放建议为 90% 到 100%，确保任务表单和 Agent 卡片清晰可读。
- 服务地址优先使用 `http://127.0.0.1:8000`。
- 如果实时模型延迟影响录制，可先使用 `http://127.0.0.1:8000/?mode=mock` 录制稳定流程，但旁白中要说明当前使用确定性演示模式。
- 录制前刷新页面，确认右上角显示“服务端编排”或“本地推演在线”。
- 录制前准备一次正常任务数据：零号大坝、3 人、稳健搜打、红狼/蜂医/露娜、31.5kg。
- 不要展示 `.env`、API Key、终端环境变量、聊天软件通知或个人文件。

## 三、逐段脚本

### 00:00-00:20 开场定位

画面：

从页面首屏开始，稍作停留。鼠标缓慢移动到右上角的状态标签，再指向主标题和五项核心指标。

旁白：

“这是 AgentProof，撤离线，一套面向撤离任务的多 Agent 协同规划平台。我们关注的不只是生成一份攻略，而是让每一条结论都有来源，每一次冲突都能被定位，每一次失败都能触发具体修正。”

屏幕字幕建议：

`有来源 / 可验证 / 可回放 / 可恢复`

### 00:20-00:45 多 Agent 定位

画面：

轻微向下滚动，展示五个 Agent 的协作入口和任务控制区域。鼠标分别经过“进入任务控制”和“查看协作链路”。

旁白：

“系统包含地图情报、风险评估、物资规划、干员协同和校验复盘五类 Agent。地图 Agent 先建立共享事实；风险、物资和干员三路并行生成草稿；校验 Agent 最后独立仲裁。它们不是各自回答同一个问题，而是分别消费上游结论，并把输出交给下一步。”

### 00:45-01:15 输入任务

画面：

进入“任务控制”。依次指向地图、行动模式、小队人数、打法、干员和总负重，不快速切换下拉框。

旁白：

“录制使用零号大坝、三人小队、稳健搜打，队伍为红狼、蜂医和露娜，总负重三十一点五公斤。输入不是一段开放式提示词，而是结构化参数。地图、人数、干员、负重和撤离条件都有明确字段，因此系统可以用工具验证，而不是让模型猜测。”

画面：

指向“开始协同规划”按钮，停顿一秒后点击。

### 01:15-01:45 地图事实与调度

画面：

保持任务按钮和 Agent 区同时可见。展示地图 Agent 从等待进入运行，再完成广播。

旁白：

“任务启动后，服务端先创建运行记录并选择 Agent 版本。地图 Agent 读取资源点、撤离条件和风险节点，通过消息总线广播给三个并行 Agent。调度器会根据角色、能力标签、任务打法、优先级和工具权限选择版本，并把选择原因写入事件记录。”

屏幕提示：

`地图事实 -> 并行草稿`

### 01:45-02:20 并行协作与第一轮审核

画面：

向下滚动到 Agent 协作链，展示风险、物资和干员卡片同时工作。随后展示消息交换区、运行日志和校验结果。

旁白：

“三个中间 Agent 先独立形成草稿，再读取彼此的结论进行二次修正。风险 Agent 判断路线冲突，物资 Agent 控制负重和烟幕，干员 Agent 安排技能覆盖与后卫接力。第一轮中，系统发现后卫未及时进入烟幕覆盖，接力延迟与风险窗口不兼容，校验 Agent 因此驳回方案，并广播具体的修改要求。”

画面：

停留第一轮红色拦截、风险分数和修改指令，至少两秒。

### 02:20-02:50 反馈循环

画面：

继续向下滚动，展示复盘分区或第二轮事件。必要时点击结果标签。

旁白：

“这里不是重新生成一段文字，而是按问题责任重新规划。路线从行政楼正门切换到装卸区外环，烟幕数量增加，后卫接应提前到第一个转折点。系统重新检查路线、风险、负重、技能覆盖和撤离条件，而不是只检查上一轮失败的单项。”

屏幕字幕建议：

`发现问题 -> 分派修正 -> 全量复验`

### 02:50-03:20 第二轮锁定

画面：

展示最终结果面板。缓慢切换“总览、路线、资源、风险、协同、仲裁”标签。

旁白：

“第二轮方案被锁定，最终分数为八十三。结果面板不仅给出结论，还列出路线、时间窗、干员、负重、撤离点和本轮修正。事件日志保存消息编号、工具调用和轮次状态，轮次快照可用于对比，也可以从失败轮次创建新的恢复分支。”

画面：

停留“撤离方案已锁定”和“已采纳”修正记录。

### 03:20-03:45 平台中心与评测

画面：

点击右上角“平台中心”。

旁白：

“平台中心展示运行记录、Agents、工作流、工具和评测。这里可以看到 Agent 版本、能力标签、工具权限和优先级。标准评测覆盖五张地图、超重负重、干员不足和高风险打法，共八个场景，全部符合预期，平均二点七五轮完成。”

画面：

切换“运行记录”“Agents”“工作流”“工具”“评测”，每个标签停留约两秒，最终停在评测页。

### 03:45-04:10 工程实现与结论

画面：

关闭平台中心。回到首页或结果页，展示顶部服务端状态，最后停在作品标题和 Agent 数量。

旁白：

“工程上，系统使用 FastAPI、SSE 和 SQLite 保存完整运行过程，提供工具注册与 MCP 接口，并支持 Docker 和本地启动。模型只在确定性事实骨架上补充推理和说明，调用失败时自动回退到规则模式。当前地图数据为竞赛演示配置，正式使用前仍需按指定游戏版本核对。”

结尾旁白：

“AgentProof 把 Agent 的输出从一段文本变成了可验证的证据链：谁提供了事实，谁发现了冲突，系统怎样完成修正，都可以被查看、回放和恢复。”

## 五、剪辑要求

- 旁白音量高于背景音乐约 10 dB，背景音乐保持低音量。
- 页面切换使用短淡入，不使用花哨转场。
- 关键步骤可加入简短文字标注，但不要遮住 Agent 卡片和结果字段。
- 等待真实模型响应时不要加速跳过全部过程，可保留部分实时日志证明系统正在执行。
- 若总时长不足 3 分钟，延长第一轮冲突、反馈指令和第二轮修正的停留时间。
- 若总时长超过 5 分钟，优先压缩首页展示和平台中心的 Agent/工作流标签，不要删除失败、反馈、复验和恢复相关内容。
